# ENSA Chad harmonisation explorer (R Shiny)

An interactive companion to the ENSA Chad 2018–2025 harmonisation. It shows **how** 14 survey rounds were made comparable, and lets reviewers explore the crosswalk workbook (`ENSA_Chad_crosswalk_2018-2025.xlsx`), the pipeline rules, the validation results and the harmonised indicators.

> **No household-level data.** The app ships only variable metadata, pipeline configuration, QC tables and aggregate indicators by round and region (cells under 30 households suppressed).

## Pages

| Page | What it shows |
|---|---|
| **Overview** | Key figures, households per round, the three questionnaire generations, the four-step approach |
| **Process** | Interactive pipeline diagram (click a step), domain status, the 336 configuration rules and the method behind each |
| **Crosswalk** | The workbook made interactive: coverage matrix (83 concepts × 14 rounds), the crosswalk table as in Excel, full variable details, a profile per concept, downloads |
| **Rounds** | Fieldwork calendar by season, concepts available per round, inventory with weight status and core checks |
| **Validation** | Agreement of recomputed FCS / rCSI with the original analysts' scores; the reversed FCS group coding; QC by round |
| **Indicators** | FCS groups and rCSI Cadre Harmonisé phases by round (weighted / unweighted, by season), region × round heatmap, regional trends |
| **Data issues** | The 20 issues found, ranked by impact, with how each is handled |
| **About** | Method, thresholds, how to reproduce, run provenance (input SHA-256), data statement |

## Run locally

Requires R ≥ 4.3 and these packages (versions tested):

```r
install.packages(c("shiny", "bslib", "bsicons", "plotly", "reactable", "visNetwork",
                   "shinyWidgets", "readxl", "readr", "dplyr", "tidyr", "jsonlite",
                   "data.table", "htmltools", "rlang"))
# tested with R 4.5.2, shiny 1.14.0, bslib 0.11.0, plotly 4.12.0, reactable 0.4.5,
# visNetwork 2.1.4, shinyWidgets 0.9.1, readxl 1.4.5
```

From the `app/` folder:

```r
shiny::runApp()
```

or in RStudio / Positron: open `app.R` → **Run App**. In VS Code, open the folder, then run `shiny::runApp("app")` in an R terminal.

## Refresh the data

`app/data/` is generated. After each pipeline run (`python run_harmonize.py` in the parent folder):

```bash
cd app
Rscript prepare_app_data.R
```

This aggregates `../output/ensa_*.csv` (household files, never copied into the app) into `data/indicators_by_round*.csv`. It also copies the QC tables, the configuration, a cleaned manifest (file names only, no local paths) and the latest crosswalk workbook. It needs `data.table` and `jsonlite` in addition to the app packages.

## Test

```bash
Rscript tests/test_app.R     # builds every page and renders every output (85 checks); exit status 1 on failure
```

## Share with the IFPRI team

All three options share aggregates only.

1. **Posit Connect / shinyapps.io** (recommended: one link, access control):
   ```r
   install.packages("rsconnect")
   rsconnect::deployApp("app", appName = "ensa-chad-harmonisation")
   ```
   Restrict access to named IFPRI accounts in the dashboard (shinyapps.io: *Settings → Users → Private*).
2. **Zip the `app/` folder** (with `data/`) and share it; recipients run `shiny::runApp()`.
3. **IFPRI / CGIAR Posit Connect server**, if available: same `rsconnect::deployApp()` call with that server registered.

Check with the data owners (SISAAP / WFP) before publishing the regional indicators outside the team.
